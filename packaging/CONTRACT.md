# Installer/release integration (step 3)

## Parent-owned interfaces
- Worker must pin repo and initial `v0.1.1`. Initial CLI installs require an explicit fixed semantic version; validate the agent's compiled version against that release before enrollment. Before executing anything, download the official project release `install.sh` to a private temporary file, verify SHA256 against Worker `INSTALL_SHA256`, then execute it. Do not pipe curl to bash. Project agent archive and installer are checked against the **same** fixed release's `SHA256SUMS`; checksum manifest is GitHub transport/repository trust, not an independent signature.
- CLI: `install.sh --control-url URL --address IP --port PORT --server-name HOST --version v0.1.1 --repo OWNER/REPO --root ROOT`. Pass one-use token using `PROXYSETTING_ENROLL_TOKEN` environment, never persistent service Environment/EnvironmentFile. `--token` is compatibility-only and exposes argv; installer disables xtrace, suppresses enrollment output, and unsets token before starting services.
- Agent: `install` accepts identical enrollment arguments except repo/version; reads token environment; its compiled version must be linkable as **`main.version`** (CI `-X main.version=v0.1.1`). It must validate literal external IP/address reachability and target TLS1.3, generate local private key and public metadata, test/register once without retrying consumed tokens, and generate `config/agent.json`, `config/xray.json`, `state/usage.json` mode 0600. Installer checks port collision before enrollment and tests generated Xray config before enabling units.
- Agent `run --root ROOT` handles API retry during startup, restores allowed users and persists counters **before** `READY=1`; sends `WATCHDOG=1` at <22s intervals only when sampling and quota enforcement are healthy. SIGTERM must complete final sample + fsync within 30 seconds. Unexpected API failure must make agent fail so systemd restarts both; agent must not continue heartbeat with a dead Xray.
- `check --root ROOT` must fail on unhealthy/stale runtime, not merely parse config; installer uses it after notify readiness. Check supports cached/offline operation: Cloudflare outage alone is not unhealthy.
- Automated upgrade must launch an independent transient service (not a child killed by the agent's stop): `systemd-run --collect --unit proxysetting-upgrade-<unique> ROOT/current/install.sh --upgrade --root ROOT --version VERSION`. **No agent repo argument required**: installer parses `ROOT/config/release.env` without sourcing it. Optional manually supplied repo must match this file. Do not launch Xray directly. Version and desired archive metadata must match the configured fixed GitHub repo release; runtime must not execute arbitrary upgrade URLs. The authenticated installer independently checks the target fixed release `SHA256SUMS`.

## Files / transactions
- Release archive: `proxysetting-agent-linux-{amd64,arm64}.tar.gz`, containing `bin/proxysetting-agent` and `packaging/proxysetting-{agent,xray}.service`. Named members are streamed, not path-extracted. Official Xray v26.3.27 ZIP is independently digest-pinned, with only `xray` extracted.
- Installed `ROOT/releases/VERSION/{bin/*,packaging/*,install.sh}`; `current` and `previous` are atomic symlinks constrained to managed releases. Root paths cannot contain spaces, traversal, or symlink components. Requires curl, tar, unzip, ss, flock, GNU coreutils; no automatic package manager or firewall modification.
- Initial install is root-only Debian/Ubuntu/Arch Linux, systemd, amd64/arm64. Nonempty root, any same-named existing service (including vendor units), port/API conflict, or invalid digest is refused. After a failed enrollment, protected incomplete files are retained; an administrator must inspect/remove them and issue a new token before reinstall. No silent overwrite/retry.
- Upgrade/rollback require root-owned exact managed unit content, expected FragmentPath, no drop-ins. Downloads/test/readiness errors restore previous config/unit/link, but **never restore usage/sequence state**. Services stop before download; agent finishes sampling while API is alive. If recovery itself fails, both services stay stopped and a protected `.installer.*/backup` is retained. Interrupted power loss/SIGKILL can leave services stopped; rerun/recover manually. Runtime should refuse stale configs/state.
- Failed staged versions are intentionally retained, not silently overwritten. Inspect/remove only their `ROOT/releases/VERSION` before retrying that version. Successful upgrade stores prior version as `previous`; manual rollback toggles between current and previous after validation.

## systemd order / safety
Agent `Wants` + `After` Xray; Xray `Before`, `BindsTo`, `PartOf` agent; Xray only `After=network.target`, **not After=agent**. Xray Type=simple starts first; agent then waits for API/restores quota and sends notify. Reversed shutdown order stops agent first for final sampling. Agent Restart=on-failure and dependency/PartOf restart both; Xray has no enable target or independent restart loop. The API must listen only on 127.0.0.1:10085. No static VLESS clients on Xray restart, so early service startup cannot grant traffic before agent restore.

## Verification / release
- Local no-host-systemd fixtures: `python3 scripts/test-install.py`; syntax `bash -n scripts/*.sh`; `nix shell nixpkgs#shellcheck -c shellcheck scripts/*.sh`.
- CI requires parent Node scripts `typecheck`, `test`, `build`, committed npm lockfile, plus `agent/go.mod`, `agent/go.sum` and `cmd/proxysetting-agent`. Verifies npm/Go/shell/mock tests on ubuntu-latest; cross-compiles CGO-disabled Linux amd64/arm64; SHA256SUMS includes installer + both tarballs. Dispatch only creates workflow artifacts; tag push creates a Release and refuses to clobber an existing release. This task never publishes a real release.
- Health: `bash scripts/check.sh --root ROOT`, `systemctl status proxysetting-agent.service proxysetting-xray.service`, `ROOT/current/bin/proxysetting-agent check --root ROOT`, `journalctl -u proxysetting-agent.service -u proxysetting-xray.service`. Check host firewall and provider security group manually; installer only warns, does not modify rules.
- Mock tests do not establish VM-level systemd notify/ordering/watchdog behavior, real GitHub asset digests, live target TLS, real enrollment, ARM execution, or cloud firewall reachability. Validate these in disposable Debian/Ubuntu amd64/arm64 VMs after parent agent integration.
