# 首页现代化与低写入流量统计

## 目标与已确认决策
- 重做管理 UI：默认进入数据首页，同时完整保留 VPS 管理、身份/逐台额度、安装/重新注册、撤销凭据、升级和 Clash Verge 导出能力。
- 首页展示每个用户的日/月/年流量排行、每台 VPS 与全站的同期用量、每日趋势和每月趋势。
- 用户已选择 **新增按日累计统计**：允许升级 VPS agent；本地统计每日增量，仍每 5 分钟打包同步，支持离线补传。不能还原的旧历史标注估算或缺失。
- 面向最多 **10 台 VPS、现有上限 50 个身份**，优先保持 Cloudflare Workers + D1 免费版，不引入付费服务、逐用户高频写入或新的部署平台。
- 本文为只读调研后的实施计划；目前未修改源代码/配置，也未运行构建或测试。

### 默认口径
- 北京时间 `Asia/Shanghai` 自然日、自然月、自然年；排行默认今日/本月/本年，并支持选择历史日/月/年。
- 流量为 Xray 记录的上行 + 下行，不是 VPS 网卡全部流量，也不是供应商账单。保留上下行拆分；展示 MiB/GiB/TiB，原始数据按字节保存。
- “总用量”指同一周期全部 VPS 的已观测用量之和；单 VPS 与全站使用同一聚合逻辑，不把日/月累计重复相加。
- 日统计属于采样计量，不宣称计费级精确：正常采样约 10 秒，跨零点无法精确切开一个采样窗口；继承当前跨月误差说明和限额行为。
- 默认云端日记录保留 **400 天**、月记录保留 **60 个月**；不持久化单独的年榜/年表，年统计由对应 12 个月聚合。超出保留范围显示不可用，不包装成永久历史累计。

### 官方免费版约束
本轮已查阅官方文档：
- [D1 Pricing](https://developers.cloudflare.com/d1/platform/pricing/)：每天 500 万读行、10 万写行，账户总存储 5 GB；INSERT/UPDATE/DELETE 均计写入，索引可能增加写行；日额度 UTC 00:00（北京时间 08:00）重置。超过免费日配额后查询会失败。
- [D1 Limits](https://developers.cloudflare.com/d1/platform/limits/)：免费单库最多 500 MB，每个 Worker 调用最多 50 次 D1 查询，单 SQL 最多 100 个绑定参数。
- [Workers Limits](https://developers.cloudflare.com/workers/platform/limits/)：免费每天 10 万请求，每次 HTTP/Cron CPU 10 ms；不能在 Worker 每次解析全年日级 JSON，也不能只关注数据库写行。
- [D1 batch API](https://developers.cloudflare.com/d1/worker-api/d1-database/)：batch 为事务，任一语句失败整批回滚；减少网络往返不等于减少计费写行。
这些是方案依据，不代表已经读取了当前账户的实时余量；同账户其他应用和攻击流量也会占用免费额度。

## UI 方案
### 技术选择
使用 **Vue 3 + TypeScript + Vite + shadcn-vue + Tailwind CSS 4**，图表使用 **Chart.js 按需注册模块**。
- shadcn-vue 只引入实际用到的组件源码，统一按钮、卡片、标签、表格、分段选择、表单和对话框的视觉；不整包引入大型后台模板。
- Vue 模板在构建时编译，使用 runtime-only 产物；图表和非首页管理页面动态导入，避免运行时编译/eval。
- 仅注册 Line/Bar、必要的坐标轴与 tooltip；日期使用已有北京时间规则和原生 Intl，不额外引入大型日期库。
- 四个页面可用原生 hash 导航与 composable 状态，不默认增加 Nuxt/SSR、Pinia、虚拟表格或复杂路由层。
- 参考：[Vue 性能指南](https://vuejs.org/guide/best-practices/performance.html)、[shadcn-vue Vite 集成](https://www.shadcn-vue.com/docs/installation/vite.html)、[Chart.js 按需注册](https://www.chartjs.org/docs/latest/getting-started/integration.html)。性能由实际产物和测试证明，不能仅凭框架名称承诺。

### 信息架构与首页布局
1. 侧栏/移动端导航：**总览、VPS、用户与额度、导出**。右上角放统计时区、最近同步、刷新、明暗主题；不新增虚假的 Basic 退出按钮。
2. 总览第一行：**今日总量、本月总量、本年总量、节点健康/已同步数量**；每张流量卡可查看上下行及数据覆盖情况。
3. **用户流量排行**作为主区域：日/月/年切换、对应日期选择、全部 VPS/单 VPS 筛选。列含名次、用户、上行、下行、合计、占比、数据质量；按合计降序，稳定 ID 打破并列，默认前 10、可展开至全部 50。
4. **VPS 用量区域**展示所有节点：名称、状态、版本/最后同步，以及今日/本月/本年上行、下行、合计；可展开查看该节点的用户分布。月份额度条若展示，明确标为“已分配用户月额度合计”，不能误称供应商 VPS 月流量额度。
5. **每日趋势**：默认近 30 天，可切换指定月份；**每月趋势**：默认本年 12 个月，可切换历史年份。支持全站/单 VPS、全部用户/选定用户；排行点选用户可联动趋势。
6. VPS 管理和额度编辑移至独立页面，使用清晰表格、详情面板、对话框替代 prompt/confirm；不删除原有危险操作确认与敏感导出提醒。

### 视觉、交互与性能
- 克制的现代后台风格：中性色背景、统一主色、卡片层次、圆角/细边框、固定数字字体、状态徽标和轻量进度条；明暗主题，390/768/1440 px 布局适配。

## 统计与低写入设计
### 云端结构：复用现有每节点 JSON
- 保留 `snapshots` 和 `usage_periods` 表及现有索引；本方案无需逐用户表、小时级时序表或年汇总表，也不默认进行 DDL 迁移。
- **月行**继续保存每个用户的月累计，维持 `desired()` 和重装额度种子语义。
- **日行**保留原有月累计观测字段以兼容历史查询，在 payload 内增加带独立版本的 `daily`：日期、用户日累计、覆盖起止、是否封存和质量。统计读取显式取 `daily`，不能误读根部的月累计 `users`。
- 新 agent 的 live snapshot 可带可选 `daily` 和至多 **一个封存 period**（日或月）；仍是每个 period 一行 JSON。64 KiB 通过最坏计数值、50 身份及 UTF-8 实际编码验证，不能一次塞数月历史。
- 封存 period 与 live month 分开校验：live 仍保持现有当前/上月容忍；archive 日只接受保留期内合法日期，archive 月只接受保留期内合法月份。过期 archive 的明确 ACK/丢弃策略不阻塞新快照。
- 每日零点封存前一天，月切换在复位前封存旧月最后累计。真实“零流量但采样健康”的日期保存零记录；服务未采样的空白日期不是零流量。

### 本地计量、补传与混合版本
修改 `agent/internal/usage/`、`model/`、`daemon/`、`control/` 和必要的安装检查：
1. 复用现有 Xray 采样和增量计算，不重复发起 gRPC 采样。日统计只累计本地观测增量，云端 `Merge` 的月额度种子/补偿不能计入当天新增流量。
2. **保持旧 `config/agent.json`、`state/usage.json` 的 v1 字段结构**。新增独立 analytics 状态、日/月小文件及扩展上传 outbox，0600/0700、O_NOFOLLOW、原子替换及 fsync；不把一年数据放进原有 1 MiB state 文件，不把扩展字段写入旧 `Pending`。
3. 新日状态的原始基线、日计数与观测时间一起原子保存；月限额状态仍是授权的权威来源。覆盖崩溃发生在两个状态保存之间的恢复：独立基线确保不重复累计，不能确定归属的窗口降为 partial，不回退月用量或用升级前备份恢复较小额度。
4. 新增仅新 agent 使用、独立设备鉴权的 `/api/agent/analytics/seed`，恢复当前日已报累计/覆盖信息；现有 register/config 响应不无条件增加字段，避免旧客户端 `DisallowUnknownFields` 失败。云端不可用时继续本地采样和缓存额度；无法确定恢复基础时明确 partial，禁止把月累计直接灌入今日。
5. 首次升级日没有完整零点基线时标为 partial；第二个完整采样日以后可给出按日累计统计。Xray 重启/计数回退、撤销用户仍有旧连接、日内时钟回退均有明确基线和质量处理。
6. 不改变已发送/已持久化旧 sequence 的 body：先按原样排空旧 pending，再用新 sequence 创建扩展封套，完整封套发送前 fsync；重试使用同一 body，ACK 后才 fsync 清除对应 archive。
7. archive 独立保留，不再随 `Prune` 的旧月快照清理而丢掉；每次正常 5 分钟上传至多附一个 archive，不启动恢复时的无界补传循环。当前状态与封存历史分离，历史积压不能把 live 日期长期锁在旧月，也不能阻塞采样/额度执法/watchdog。
8. 处理回滚后旧程序仅上传 base snapshot 的情况：不因 latest sequence 已接受就把未确认 analytics/archive 当作完成；使用新序号重排幂等封存记录，旧程序忽略新增统计文件但仍正常执行额度。
9. 默认本地 archive 保留期与云端匹配，逐日小文件避免每 10 秒重写全年历史；有界清理。丢失本地未上报状态或离线超出保留期属于无法恢复的数据缺口，不伪造为完整统计。

### 服务端幂等与竞态
在 `src/worker/routes/agent.ts` 抽出 period 校验/写入 helper：
- 最新快照、当前月/日、至多一个 archive、节点状态在同一个 D1 batch 提交。
- **第一条快照写和后续写**都检查当前凭据仍有效、VPS 未撤销与获胜 sequence，不能只在请求入口鉴权后假定其一直有效。
- 累计不回退校验进入事务内的条件写/合并，不能只依赖 batch 之前读取旧快照；覆盖更高 sequence 但较低计数与并发乱序请求。
- 月/日用户按稳定 ID 保留历史并做方向级单调校验/恢复合并，不因移除 grant、用户停用或 payload 缺用户丢掉已发生流量。
- 重新注册清 latest sequence 不清历史 period；较低的重装累计不能覆盖已存月/日累计，完整 daily 不被旧格式日快照降级。
- 去重重传不重写已相同的 period；duplicate 请求仍有设备限流写入，这是预算的一部分。对未提交/未确认 archive 不能仅返回 latest duplicate 就吞掉历史。
- 单用户方向值及其和遵守原有安全整数限制；跨用户/跨月汇总在浏览器使用 BigInt，图表值仅作单位换算后的可视化，避免年榜溢出 `Number.MAX_SAFE_INTEGER`。

### 只读统计 API 与聚合
新增 `src/worker/routes/analytics.ts`，由现有管理鉴权保护；前端新增 `src/web/lib/analytics.ts` 和 API/composable：
- 有界日范围接口：每请求最多 7 天，旧历史差分额外取一个前置观测日；有界月范围接口：每请求最多 6 个月。返回必要计数 JSON/观测元数据，不返回 UUID、凭据或配置秘密。
- 使用合法日/月 period 的精确 `IN` 参数查询及现有索引；年读取对应 12 个 **月 period**，不能使用含日行的模糊年份匹配，也不扫描全年日快照。
- D1 可投影必要 JSON 部分，Worker 不循环解析整年用户数据；小范围结果交浏览器统一聚合排行、节点用量和趋势。首页先加载当日和月份摘要，趋势分段补齐，限制并发与重复请求。
- 客户端用同一纯函数产出所有视图；月/年不从日估算值相加，避免与额度恢复的月累计不一致。
- 停用/撤销授权的历史用户仍计入，名称缺失时以历史身份 ID 占位。无记录和已测量零流量区分显示；部分节点缺数据时标注“已同步用量/不完整”，不是完整全站总量。
- 旧日记录：只有同月、连续且方向计数不下降的有效观测才可差分，标记 estimated；首条、跨月、缺日、回退和无足够基线显示 missing/partial，不均摊离线流量、不把全部月累计归到第一天。
- 当月/当年和当前日为进行中，已封存且覆盖完整的 period 才能称完整。API 仅 SELECT，禁止浏览页面时写排行榜、cache 或计量行。

### 保留与清理
在 Worker 加 `scheduled`，`wrangler.jsonc` 配每日一次小型 Cron（例如 UTC 00:15）：
- 清理超过 400 天的日行、60 个月的月行及过期注册限流键；保留当前有效 device 限流记录，避免每日删除后再插入。
- 每次有界删除（例如历史最多 20 行、注册键最多 20 行），记录实际 `rows_written`，包括索引删除成本；按积压逐日推进，不在首页读请求上清库。
- 不生成 Cron 日/月账单，也不使用 Cron 遍历全部用户聚合；CPU 仍受 10 ms 限制。普通保留清理目标约百行计费写入/日，异常积压需要单独运维处理。

## 免费写入预算与验收阈值
设节点数 N ≤ 10，配置 60 秒、上传 300 秒：
| 场景 | 每日逻辑写行（尚未包含所有索引/管理成本） |
|---|---:|
| 所有有效设备请求的限流写 | N × (1440 + 288) |
| 正常快照 latest + 月 + 日 + VPS | N × 288 × 4 |
| 10 台全在线常态合计 | **28,800** |
| 每次快照都附一个 archive 的满载补传 | 28,800 + 10 × 288 = **31,680** |
| 假设每个 archive 插入再产生两次索引写的保守示例 | 31,680 + 2 × 2,880 = **37,440**，还需加当天新行、seed、维护和管理成本 |

- 常态额外封存：约 N 个日最终值/日、月初另 N 个旧月最终值；通过同一个 archive 槽分批发送，无需给每个用户写一行。
- 对比逐用户方案，仅 `10 × 50 × 288 = 144,000` 次计数行写入/日就已超过免费上限，尚未计限流和索引，明确拒绝。
- **发布验收目标**：10 VPS/50 身份、一个可见管理页按 5 分钟刷新、正常同步及限速满载补传，基于实际 D1 meta/指标外推 **≤50,000 写行/日**、正常读量目标 **≤2,000,000 行/日**、正常请求总量 **<25,000/日**。这些是待测目标，不是已验证的生产数据。
- 如果实际成本不满足，优先减少重复 period 更新、修正索引/查询和补传速度；不以增加每用户行、放宽配额或偷偷升级付费解决。对额外管理流量/多标签/同账户其他业务单独说明余量。
- 约 4,000 日行 + 600 月行；按真实 UTF-8 payload 大小和索引计算空间，日 JSON 约 8–16 KiB 时日数据约 32–64 MiB，另加月数据/SQLite 索引，验收实际库体积距离 500 MB 保持充足余量。不能用账户 5 GB 当作单库上限。
- 写指标只从 D1 `meta.rows_written/rows_read`、控制台或外部日志获取，不为记录每次成本再高频写 D1；页面显示“预算估算”，没有实时账户指标时不得伪装实时剩余额度。

## 验证计划
### 自动化正确性
- Go：同日多次采样、日切换/月切换/闰日/年切换、时钟回退、Xray 重启和方向回退、禁用用户旧连接继续计量、月额度种子不计入日增量、真实零流量。
- 故障与兼容：日状态与月状态不同写入点崩溃；ACK 成功但本地 fsync 前崩溃；序号与 outbox 恢复；数日/跨月离线补传；归档过期/队列上限/64 KiB；旧 config/state 被旧二进制严格解码；回滚后月额度不回退、新版再启动不重复补传。
- Worker/Miniflare：日/月 JSON 含义、旧快照兼容、较新 sequence 配较低计数、并发乱序、撤销/轮换与写事务竞态、重装后低计数、完整 daily 不被 legacy 覆盖、同一 archive 重传不重复写。
- 浏览器聚合纯函数：跨 VPS 汇总、日/月/年排行、停用历史用户、单位/占比、稳定并列、BigInt 年合计、缺数据不补零、估算/partial 传播；完整覆盖情况下各用户之和 = 各节点之和 = 全站总量。
- 路由：非法日期/范围/未知 VPS、权限拒绝、查询绑定参数、月查询不混入日行；统计 GET 的 DB 写入为 0。

### UI、构建与安全
- 执行 `npm run verify`（扩展后包含 Web 类型检查/build、Vitest、本地 D1 检查和 Worker dry-run）、`git diff --check`；Go `go test ./...`、`go test -race ./...`、`go vet ./...`；`python3 scripts/test-install.py` 与 shell 检查。
- 新增最小 Playwright 浏览器验收（HTTPS、Basic httpCredentials）：390/768/1440 px、明暗主题、排行切换/筛选与趋势联动、空/错误/过期/部分数据、表单不丢编辑、键盘/弹层、复制/下载及关闭清理敏感安装命令。
- 检查 CSP 控制台无违规，构建 assets 路径/刷新均正常；匿名 HTML、哈希 JS/CSS、统计 API 仍 401；agent 仍独立 Bearer，不弹 Basic。
- 前端性能目标：应用壳 JS+CSS 不含懒加载图表/管理页 **≤200 KiB gzip**，图表 chunk **≤100 KiB gzip**；10×50 夹具中筛选/切换无持续长任务，图表更新与用户交互目标 <200 ms。未达标时按组件/图表模块裁剪，不换用重后台模板。

### 免费版与真实上线验收
- 用 10 VPS/50 用户的 24 小时逻辑夹具覆盖正常、重复、首次建日、月底、满载补传和清理；汇总每条 D1 返回 meta（含索引），说明哪些数据来自本地模拟、哪些来自真实 D1。
- 真实暂存/测试环境验证 Worker HTTP 与 Cron CPU，目标 p95 留出余量（约 ≤8 ms），不得依赖偶发宽限；测试有界日/月响应最坏 payload，记录 D1读写和空间。若不符合 10 ms，先缩小分段/投影，不扫描全年用户 JSON。
- 上线顺序：备份 D1 和 UUID_KEY → 发布兼容旧 agent 的 Worker/静态站 → 发布不可变新 agent Release → 先升级一台 → 核验采样、月额度、日统计/ACK及跨日 → 再逐台升级其余节点。修改安装器时重新审核 SHA256，不覆盖旧 Release。
- 暂停/恢复控制面网络验证离线日文件和补传限速；云端失败仍执行原有本地额度策略。真实跨日/月运行和浏览器操作需要外部环境，mock 通过不替代上线验收。

## 风险、非阻塞事项与拒绝的替代方案
- 最大正确性风险是把月累计当日用量、把远端种子当新流量、重复补传相加，以及月末最终值丢失；需先做统计链路再接 UI。
- 独立日计量不会补出升级前完整历史。升级当天、丢本地状态和跨零点采样误差必须展示质量；不以“精确账单”描述本方案。
- 新旧 agent 混跑时，各节点日数据质量不同；页面显示支持情况，不要求一次重装全部 VPS。旧版本返回的统计字段不能导致其严格 JSON 解码失败。
- 保留期是默认实现常量，后续可按实际存储调整；超保留期不会声称仍有数据。无需在本次增加复杂保留策略配置 UI。
- 账户共享免费额度、公网上游攻击、过多管理刷新不是本项目能保证的预算；D1 限流自身也耗写入，继续保留边缘防护/余量告警建议。
- 拒绝：仅美化旧页面却用错误日快照排行；每用户每 5 分钟写行；高频上传/秒级首页刷新；新增付费 Durable Objects/时序库；为年榜重复写第三份计量；Cron 全年全用户聚合；Nuxt/SSR 与整包大型 UI；全量历史回填伪造按日精确值；放宽现有脚本安全策略。
